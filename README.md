# Image Workbench for Mac

**Mac（macOS / Apple Silicon）向けの画像編集・画像生成アプリです。**

Qwen Image 2.1 を日本語の Gradio 画面から利用し、Apple Silicon の GPU（MPS）で Mac 上のローカル推論を実行します。Apple Silicon / メモリ 128 GB の環境で動作確認済みです。必要なメモリは生成設定によって変わります。

## 起動

[uv](https://docs.astral.sh/uv/) と Python 3.12 を使用します。

```bash
uv sync
uv run python app.py
```

ブラウザで http://127.0.0.1:7860 を開きます。モデルは初回実行時に Hugging Face からダウンロードされ、通常は `~/.cache/huggingface/hub/` にキャッシュされます。モデルは約 33 GB です。API キーは不要です。

同じ LAN の別マシンからは `http://<起動したマシンのIPアドレス>:7860` を開きます。
既定では `0.0.0.0` で待ち受けます。待ち受け設定の変更を反映するには、起動中のアプリを Ctrl+C で停止して再起動してください。

## 使い方

- **Image to Image**: 参照画像を 1〜10 枚アップロードし、編集指示を入力して「画像を生成」。参照番号はアップロード順です。
- **参照画像の付け直し**: ドロップ欄は取り込み後も残ります。「入れ替え」（初期設定）で次の画像に差し替え、「追加」で既存の画像に追加できます。「参照画像をクリア」で全画像を外せます。
- **生成画像を続けて編集**: 生成結果の下の「この生成画像を参照画像にする」を押すと、その画像1枚を参照画像に設定してImage to Imageへ切り替えます。次の指示を入力して再び生成できます。
- **参照画像プレビュー**: アップロード後に1枚目の画像全体を表示します。下のサムネイルで画像を切り替え、右上の全画面ボタンで拡大できます。生成結果にも全画面ボタンがあります。
- **編集指示を整える**: Image to Image で参照画像と短い指示を入力し、このボタンを押すと、補助モデルが画像を見ながら詳しい編集指示に書き直します。指示欄に戻った文章を確認・修正してから「画像を生成」を押してください。
- 通常モードは専用の短い指示で簡潔な編集文を作り、必要な文章が完成した時点で処理を終えます。補助モデルに渡す参照画像は合計約100万画素を目安に縮小します（元画像や画像生成の解像度は変えません）。小さな文字や細部を詳しく検討したい場合は「詳しく検討する」をオンにしてください。時間と出力内容は検討モードによって変わります。
- 処理中は生成トークン数と経過秒数を表示します。通常モードの文章生成は最大768トークン・75秒を目安に打ち切ります。モデル読み込みや画像前処理は別途かかり、実行中の1回の演算は中断できないため、処理全体の秒数の保証ではありません。文章が完成しなかった場合は警告を出し、元の指示を保持します。そのまま「画像を生成」に進めます。
- 同じ画像・指示・検討モードで再度押した場合は、直前の結果を再利用します。整えた文章をそのまま再実行した場合も再利用し、繰り返し文章を膨らませません。画像の内容・順序、文章、検討モードを変更すると再計算します。「モデルを解放」またはアプリ終了で再利用結果を消去します。
- **Text to Image**: モードを切り替えて文章から画像を生成。
- **幅と高さを入れ替える**: 生成設定のボタンで縦横を交換します。例えば 1024×768 → 768×1024 に切り替えられます。
- 透明背景のチェックを入れると、公式推奨の RGBA 指示をプロンプトに追加します。透過結果はモデルの出力に依存します。保存時にアルファチャンネルを保持します。
- シード `-1` はランダム。生成情報に実際のシードを記録します。同じ結果の再現にはプロンプト・画像・解像度・ステップ数・環境も揃えてください。
- PNG と生成設定 JSON は `outputs/` に保存され、画面からダウンロードできます。
- **進行状況・所要時間**: 生成結果の上に現在の処理と経過時間を表示します。モデル読み込み中も時計が進み、生成中はステップ数、指示整理中は生成トークン数が分かります。画像生成と指示整理の直近の所要時間をそれぞれ残し、読み込み／推論の内訳や前回結果の再利用も表示します。合計時間は処理開始から保存・モデル解放などを含む終了までで、キューでの待ち時間とブラウザ通信は含みません。
- **ボタンと状態の色**: 実行できる操作ボタンは青緑、入力不足・処理中などで押せないボタンはグレーです。理由は生成ボタンの上に表示します。処理中は黄色の「現在生成中」「現在指示を整理中」と経過時間を表示し、完了は緑、未完成はオレンジ、失敗は赤で示します。処理中は参照画像・指示・生成設定の変更と重複実行を止め、完了・未完成・失敗後に操作を戻します。
- **実行ログ**: 生成結果の下の「実行ログ」を開くと、その実行の進捗・Pythonログ・警告・エラーを最新200行まで確認・コピーできます。実行ごとにリセットし、別のブラウザの実行ログは混在させません。コンソール全体の転送ではないため、ライブラリが直接出す文字やダウンロードの端末用プログレスバーは含みません。
- ログは初期設定で最新行へ自動スクロールします。過去ログを読むときは「最新行へ自動スクロール」をオフにし、「最新行へ」ボタンで末尾に戻れます。オンに戻したときやログ欄を開き直したときも末尾へ追従します。

通常のHTTP通信のINFOログと、`causal_conv1d` / `flash-linear-attention` が未インストールであることを知らせる4種類の既知のフォールバック警告は非表示にしています。推論の動作は変えず、その他の警告・エラーは残します。Diffusersの読み込み引数は非推奨の `torch_dtype` から `dtype` に変更しています。

画像生成・編集ともに `Qwen/Qwen-Image-2.1` を使用します。

編集指示の補助には、追加学習済みの視覚言語モデル [`Qwen/Qwen-Image-2.1-PE-I2I`](https://huggingface.co/Qwen/Qwen-Image-2.1-PE-I2I) を使用します。ボタンを初めて押したときに約 18.8 GB のモデルを追加ダウンロードし、以降はローカルキャッシュを使います。画像と指示の処理はローカルで行います。補助モデルの出力によっては日本語以外の文章になる場合があります。画像の幅・高さは画面の設定を使い、補助モデルが提案するアスペクト比では変更しません。

## 実行環境

CUDA → Apple Silicon MPS → CPU の順で自動選択します。生成は既定で 1024×768 px（幅×高さ）/ 40 steps。CPU 推論は非常に時間がかかります。Apple Silicon 対応は MPS を利用し、未対応の演算は PyTorch の CPU フォールバックを有効にしています。モデルのロードと推論には十分な空きメモリが必要です。

CUDA では既定でモデル CPU オフロードを有効にします。MPS はメモリ上にモデルを配置します。一度読み込んだモデルを生成・編集の両方で再利用します。同時推論は 1 件に制限しています。「モデルを解放」でメモリを解放できます。

編集指示の新しい計算を行うときは、画像生成モデルを解放してから補助モデルを読み込みます。補助モデルは処理後に解放するため、その後の画像生成では画像生成モデルを再読み込みします。前回の指示を再利用する場合はモデルを読み込まず、読み込み済みの画像生成モデルも保持します。指示の補助・画像生成・モデル解放は同時に実行しません。

| 環境変数 | 既定値 | 用途 |
| --- | --- | --- |
| `QWEN_DEVICE` | `auto` | `auto` / `cuda` / `mps` / `cpu` |
| `QWEN_CPU_OFFLOAD` | `1` | CUDA で CPU オフロード。`0` で無効 |
| `OUTPUT_DIR` | プロジェクト内 `outputs/` | PNG・設定 JSON の保存先 |
| `HF_HOME` | Hugging Face の既定値 | モデルのキャッシュ保存先 |

```bash
QWEN_DEVICE=mps uv run python app.py --port 7861
```

このマシンからだけ利用する場合は `uv run python app.py --host 127.0.0.1` で起動します。

## 開発・検証

```bash
uv run pytest -q
uv run ruff check .
```

単体テストは大きなモデルを読み込まず、入力検証・参照画像順序・シード・透過 PNG 保存・推論への引数を確認します。実モデルの品質・速度の検証は別途推論が必要です。

ドラッグ＆ドロップ、2回目の編集、成功・失敗後の操作復帰、ボタンの色、ログの自動スクロールをブラウザで検証する場合:

```bash
uv run --with playwright python -m playwright install chromium
uv run --with playwright python tests/browser_ui.py
```

推論はテスト用の処理に置き換え、専用の一時プロファイルを持つ画面非表示のブラウザを使います。普段のChromeのプロファイルや同期を使わず、検証用サーバーは終了時に停止します。画質・実モデルの速度の検証ではありません。

学習済みモデルで生成→編集をまとめて確認する場合:

```bash
uv run python smoke.py --size 512 --steps 2
```

2 steps は動作確認用です。画質を確認する場合は `--steps 40` を指定してください。

補助モデルによる指示の書き直しも含めて、生成→指示の補助→編集を確認する場合:

```bash
uv run python smoke.py --size 512 --steps 2 --enhance
```

2026-09-21 に Apple Silicon / メモリ 128 GB / MPS で確認済み:

- 単体テスト 12 件、Ruff チェック成功。
- 実モデルで 512×512 / 40 steps / seed 42 の Text to Image が約 13.5 秒（ロード後）。
- 生成した赤いティーポットを青に変える Image to Image が約 22.4 秒。
- Gradio 画面で生成結果・PNG ダウンロードを確認。編集は Gradio API 経由で確認。

上記はこの環境での測定値です。解像度・参照画像数・ハードウェアによって変わります。

2026-09-22 に同じ Apple Silicon / MPS 環境で、補助モデルによる日本語の編集指示の書き直しと、生成→指示の補助→編集（512×512 / 2 steps）を確認しました。単体テスト33件と Ruff も成功しています。2 steps の検証は処理の接続確認であり、画質の比較評価ではありません。

同日の速度改善検証（512×512 の参照画像1枚、ティーポットを青くする指示、補助モデルの乱数seed 42、モデル取得済み）では、変更前は1回目80.40秒・2回目77.44秒でした。通常モードに変更すると初回23.59秒、同じ条件の再実行は前回結果の再利用により0.003秒でした。いずれもバックエンドの処理時間で、ブラウザ通信を含みません。画像・指示によって時間と出力は変わります。単体テスト41件・Ruff と、ブラウザでの縦長／横長プレビュー、全画面表示、縦横交換後の768×1024の実生成を確認済みです。

その後、通常モードで長時間待った後に回答の解析が失敗する報告を受け、通常モード専用の指示、回答開始位置の固定、完成した指示文での早期終了、参照画像の画素数制限を追加しました。報告された入力と同一条件の再現は未確認ですが、同じMacで取得済みモデルを使い、ローカルのGradio API経由で3072×4096の参照画像1枚の色変更が16.84秒、指示を変えた再実行が15.09秒、同じ入力の再利用が0.12秒で完了しました。参照画像10枚のコラージュ指示も完成し、モデル読み込み7.64秒・文章生成10.21秒でした。日本語のタイトル・価格など複数の文字を指定した指示も確認済みです。回帰テスト59件・Ruffが成功しています。これらは速度の保証や画質評価ではありません。

Diffusers は Qwen Image 2.1 対応済みコミットに固定しています。依存バージョンは `uv.lock` で固定します。

進捗表示の追加後、テスト73件とRuffが成功。ローカルGradio APIで、モデル読み込み中の経過時間の連続更新、512×512 / 2 stepsの画像生成、編集指示の作成、前回結果の再利用、完了時の時間・ログ出力を確認しました。別実行のログ分離、失敗・未完成時の入力保持、ブラウザ切断時の実行管理は回帰テストで確認しています。この時点ではAPIでの確認のみでした。

続くUI改善ではテスト85件・Ruffと、テスト用推論を使ったブラウザ操作の検証が成功。実際のドロップ操作による画像の入れ替え・追加、生成画像の参照への転用、2回目の編集、成功・失敗・未完成後の操作復帰、実行中の入力制限、ログ追従のオン／オフ・再表示を確認しています。専用の画面非表示ブラウザでデスクトップと幅390pxの画面を確認し、通常のChromeのプロファイルや同期は使用していません。
